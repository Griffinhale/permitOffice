## 2. Findings by lens

### Algorithmic complexity (#2, #7, #17, #21, #22, #23)

- **#2 — `max()` over `sorted()[0]`** (`helpers.py:694-744`). `_top_dissatisfaction`,
  `_top_presence_group`, `_top_dissatisfaction_for_profiles`, `_strongest_template_group` all sort
  ~12 items to take one. → `max(items, key=…)` with the *same* `(-band, group)` key (ties identical,
  determinism preserved). Keep `sorted` only where genuine top-k is consumed. `self_check`: holds.
- **#7 — `rebuild_type_ledger` single pass** (`type_pressure.py:13-50`). 6× full filter+sum over 25
  profiles (one per district type). → one bucketing pass + O(types) finalize. Small N, clean win.
- **#17 — single-winner sorts in desk summaries** (`desk_model.py:688-890`). `_strongest_group`,
  `_top_grievance`, `_service_gap_summary`, etc. sort to extract the worst/top-3. → `max(...)` /
  `heapq.nlargest`, identical composite keys for tie-breaks.
- **#21 — `validate_feature_catalog` step-index** (`helpers.py:189-194`). O(T·C·S) nested scan to
  validate one `project_step_id`. → build `{step_id: set(chain_ids)}` once. Validation-time only
  (`hotness: rare`), so impact low but the O() drop is real.
- **#22 — weighted template sampling** (`profiles.py:200-214`). Sampling loop re-`sum()`s and
  re-`sorted()`s the full remaining dict each pick. → pre-sort once + running total. **`confidence:
  med`** — *fragile*: must reproduce the exact `rng.randrange(total)` draw sequence.
  `constraint: ADR-11 — verify against the seed-2026 regression before adopting.`
- **#23 — `_suggest_targets` top-k** (`geometry.py:375-389`). Full `sorted()` of N districts to take
  `[:1]`/`[:2]`. → `heapq.nsmallest(2, …)` for POINT/POLYGON; LINE keeps the full sort (it scans
  `ordered[1:]`). rng draw order unchanged. `constraint: ADR-11 — nsmallest doesn't change draw order.`

### Data-structure fit (#3, #6, #20, #29, #32, #34)

- **#3 — frozenset companions for catalog constants** (`models.py:13-60`). `CITIZEN_GROUPS` /
  `SERVICE_TYPES` / `HAZARD_TYPES` are tuples hit by ~49 `in` tests (linear, k≈12) on per-turn paths.
  → add `*_SET = frozenset(...)` for membership; **keep the ordered tuples for iteration/sampling**.
  `constraint: ADR-11 — ordering tuples retained, frozenset used only for membership.` This is the
  root fix several other findings (#6, #20, #29) point back at.
- **#6 — `_normalize_service_map` keys** (`helpers.py:410-425`). Per call does `tuple(allowed)` then
  linear membership — and callers already pass module tuples, so the copy is pure churn. Runs ~6×
  per `normalize_profile`, which runs ~100+×/turn. → frozenset companions, drop the copy.
- **#20 — status tuples in turns loops** (`turns.py:67-78`). The 2-element status tuples are
  negligible; the real cost is the 12-element `CITIZEN_GROUPS` membership in helpers — *subsumed by
  #3*. Listed for completeness.
- **#29 — frozenset fit-types on `DocketTemplate`** (`templates.py:27-29`). `good_fit_types` etc. are
  tuples hit ~625×/docket in `_weighted_template_pool`. k=2-3 so absolute win is marginal.
  **`confidence: med`** (small k). See cross-module lead — the geometry adapter is a *second*
  consumer of these same tuples.
- **#32 — `read_state` double subscript** (`store.py:188-197`). `values[key][1] is not None` then
  `int(values[key][1])` — two lookups. → bind `entry = values.get(key)` once. Genuinely tiny.
- **#34 — reuse `active_items` + frozenset `ACTIVE_STATUSES`** (`desk_model.py:16,185`).
  `_ticker_items` re-scans the docket for `open_count` that `build_desk_model` already computed as
  `active_items`. → pass `len(active_items)` in; make `ACTIVE_STATUSES` a frozenset.

### Redundant computation (#1, #4, #5, #8, #10–16, #18, #19, #26, #27, #28, #30, #31)

- **#1 — double `normalize_profile` in cascade callers** (`systems.py:22-60,255`). *The only
  high-impact item.* `apply_stat_cascade` ends with `normalize_profile` (line 56); `apply_hazard_turn`
  calls it **again** at line 256 with no field mutation in between (hazards set *before* the cascade).
  `normalize_profile` is heavy (~6 12-key band rebuilds + 2 service-map rebuilds + derived-text) and
  the cascade runs ~50-100×/turn. → drop the redundant trailing normalize where the caller doesn't
  mutate post-cascade. **`confidence: med`** — `apply_hazard_turn` is clearly redundant; the
  `apply_housing_dynamics`/`apply_template_long_term_effects` callers need a per-caller mutation trace.
- **#4 — single-pass `_scenario_score`** (`turns.py:119-128`). ~17 separate linear passes over the
  same profile list (5 metric sums + per-service + per-hazard). → one accumulating pass, weight-gated.
  `generate_audit_result` walks the same profiles again (355-376) — see leads for the overlap.
- **#5 — reuse normalized maps** (`helpers.py:326-347,700`). One `normalize_profile` triggers ~4-5
  extra full band rebuilds + sorts on maps it *just* normalized (via `public_profile_for`,
  `_refresh_incident`). → thread a normalized flag / pre-computed tops through the derived-text
  helpers. `confidence: med` (threads state through several helpers).
- **#8 — `weekly_pressure` double `.get`** (`turns.py:181-208`). Read into `max(...)` then again at
  line 204. → bind `cp` once per cid.
- **#10 — city forecast computed 4× per desk build** (`desk_model.py:364-527`). The heaviest repeated
  build computation — same `(template, targets)` → identical string, recomputed in City bucket,
  `_local_bucket_value` (×2), and `_action_lanes`. → compute once in `_case_summary`, pass cached.
- **#11 — archetype lookup ~10× per build** (`desk_model.py:322-579`). → resolve once and thread, or
  `lru_cache` on the rules side. `constraint: keep the cache on the rules module so the adapter stays pure.`
- **#12 — hoist invariant template attrs** (`profiles.py:149-183`). Per-district re-reads of
  district-independent template fields + 3 separate passes over `districts.values()`. → pre-extract
  per-template tuples, fold the district passes into one. Constant-factor, deterministic.
- **#13 — `_feature_spatial_weights` twice per turn** (`systems.py:182-257`). `recompute_network_access`
  and `apply_hazard_turn` each compute it for the same features/adjacency, called back-to-back from
  turns.py. → compute once per turn, pass into both. (See the matching cross-module lead.)
- **#14 — skip normalize+encode for unchanged district rows** (`store.py:427-467`). `UpdateCursor`
  (no WHERE — a 25-row write) re-normalizes + re-encodes JSON for *every* row including unchanged.
  → dirty-set scope the normalize+encode. **`confidence: med`** — relies on `normalize_profile` being
  idempotent (unverified) and skipped rows truly unchanged. `constraint: verify idempotency first.`
- **#15 — WHERE-filter `write_active_features`** (`store.py:584-616`). `UpdateCursor` (no WHERE) scans
  every row of points/lines/zones for a few matched ids. → push a `WHERE IN` list, or at minimum skip
  opening a cursor on a class with no matching ids. **`confidence: med`** (IN-list length/quoting).
  *Distinct from the already-shipped single-row WHERE work — this is the multi-row write.*
- **#16 — single-pass severity in `inspection_case_for_item`** (`profiles.py:547-553`). 3 passes over
  evidence + a literal weight dict rebuilt per record. → hoist `SEVERITY_SCORE` constant, one loop.
- **#18 — cache label-index dicts off the draw path** (`desk_view.py:275-587`). `_draw_top_banner` /
  `_draw_ledger_rail` / `_draw_case_controls` rebuild `{label: row}` / `{action_id: lane}` **every
  frame** (~1/s + per hover) from frozen tuples. → build once per model change, invalidate on swap.
- **#19 — memoize `_fit_px`** (`desk_view.py:769-794`). Binary-search text-fit re-run every frame for
  unchanged strings. → instance memo keyed by `(text, size, weight, max_px)`, cleared on model change.
  `confidence: med` (short labels already fast-path).
- **#26 — memoize joined `scenario_tags`** (`store.py:726-732`). `",".join(TEMPLATES[id].scenario_tags)`
  per row + per `write_docket_item` (~7×/action), static per template. → module-level cache.
- **#27 — drop `ListFields` scan in `selected_cell_ids`** (`geometry.py:48-68`). Per-call field
  enumeration + dict to resolve the fixed `cell_id` column. → try `cell_id` directly, fall back to
  `ListFields` only on cursor error.
- **#28 — frozenset keys + drop double sort in `_clamped_int_map`** (`store.py:234-299`). Rebuilds
  `set(allowed)` per call (~75 allocs/read) **and** returns `dict(sorted(...))` that callers
  immediately re-sort via `json.dumps(sort_keys=True)`. → shared frozensets + return unsorted for the
  encode path. **`confidence: med`** (a decode caller may rely on dict order — not fully traced).
  `constraint: serialized JSON stays sort_keys=True, output byte-identical.`
- **#30 — collapse second `proposal_visible` dict in `reload`** (`dashboard.py:280-283`). The per-item
  cursor scan was already removed in 7e0a22e; the residual second comprehension + no-op `bool()`
  coercion survives. → drop it / read membership directly. `confidence: med` (consumer not traced).
- **#31 — hoist corridor-cell set** (`generate_city_detail_features`, `city_detail.py:69-72`).
  `set(horizontal + vertical)` rebuilt every loop iteration. → hoist above the loop. New-Game only.

### Allocation & lazy eval (#9, #24, #25, #33)

- **#9 — hoist target-profile list in `resolve_decision`** (`decisions.py:118-281`). `[districts[cid]
  for cid in targets]` rebuilt ~8× per action (verified built twice back-to-back at 118-119). → bind
  once near the top, reuse. Helpers consume it read-only (iterate, never reorder), so it's safe — and
  this also kills the cross-module re-walk (see leads).
- **#24 — generator `_open_violations`** (`turns.py:451-457`). Materializes a filtered list consumed
  once by the enclosing loop. → `yield`. Sole call site only iterates, so behavior-identical.
- **#25 — shared frozenset `active_status`** (`systems.py:166-179`). `{active, settled, …}` literal
  rebuilt every `active_feature_instances` call (~2-3×/turn) + related literals at 489/553. → one
  module-level frozenset.
- **#33 — replace-only the changed report tab** (`desk_model.py:206-219`). Whole `report_tabs` tuple
  reconstructed to flip one `selected` flag. → `dataclasses.replace` only the differing tab.

## 3. Further leads (UNVERIFIED — what the per-region sweep was blind to)

The region partition can't see patterns that span modules or that live in functions a finder marked
"out of region." The critic surfaced these by reading across the boundaries. **These are leads, not
findings — verify before acting.**

**Cross-module:**

1. **Scorecard re-normalizes all 25 districts on the *render* path.** `_ledger_rows`
   (`desk_model.py:836`) calls `rules.scorecard(state, deepcopy(districts), …)` on **every**
   `build_desk_model` (i.e. every reload/action), and `scorecard → generate_audit_result`
   (`turns.py:323`) loops profiles calling `normalize_profile` (line 356) + `_scenario_score`'s ~17
   passes — just to render the ledger "Audit" row. The `deepcopy` means the normalize work is then
   *discarded*. No region-finder saw this: desk_model finders marked scorecard out-of-region; rules
   finders (#1, #4) costed normalize/aggregates only on the *turn-advance* path. **This is likely the
   single biggest real win available** — cache the grade off the last turn-advance or memoize on
   `(state, districts)` identity so render doesn't re-derive it. (Note: coverage claims it's "memoized
   per ADR-4", but `generate_audit_result` re-normalizes *inside* the build regardless of the
   read-state memo.)
2. **Per-action triple GDB read.** One click: `active_item()` (`dashboard.py:676`, full `read_docket`)
   → the handler reads `read_state`/`read_districts`/`read_active_features` → then `reload()` reads
   `read_districts`/`read_docket`/`read_active_features` **again**. So one action opens the docket
   cursor ~3× and the districts cursor ~2×. Split across dashboard (adapter-geo-ui) and store
   (adapter-store), so no finder owned it. → a per-action read cache, or thread already-read objects
   into `reload()` via its existing `state=`/`districts=`/`items=` kwargs (`inspect` already does this
   for `state` only).
3. **`_feature_spatial_weights` shared caller is `turns.py`** (extends #13). turns.py:234/235 call the
   two functions back-to-back over identical features/adjacency — compute weights once *there* and
   thread into both, rather than fixing each function in isolation.
4. **`active_feature_instances` list rebuilt ~4× per turn** from one `feature_list` that `turns.py`
   already holds (extends #25). The filter+membership runs independently in `recompute_network_access`
   and `apply_hazard_turn`; turns.py could compute the active subset once and pass it down.
5. **Catalog tuples are consumed in *two* layers.** `template.good_fit_types` etc. are hit by
   `_weighted_template_pool` (rules) **and** `_suggest_targets` (`geometry.py:367-374`, adapter). #3/#29
   only traced the rules call site — a frozenset on the catalog dataclass fixes both at once.
6. **`resolve_decision`'s target list is a cross-module hand-off** (extends #9). It's built in
   decisions.py and passed read-only into `_apply_population_reaction` / `_surface_new_incidents` /
   `apply_template_long_term_effects` in helpers.py/systems.py — confirming the read-only contract that
   makes the single-hoist safe.

**Coverage gaps (lenses/areas under-applied):**

- **Allocation lens is thin** (4/34 findings, all micro). The big allocation sinks were never lensed:
  `_ledger_rows` does `deepcopy(districts)` + `_feature_snapshots(active_features)` + `deepcopy(docket)`
  on every build; dashboard handlers re-read full GDB tables several times per action. A dedicated
  allocation/IO-churn sweep of the dashboard+desk_model render path is missing.
- **`buyouts.py` (311 L) and `expiration.py` got zero findings** despite being on the End-Week path.
  `_eligible_bidders`/`_eligible_target` scan adjacency per district; `resolve_buyout_round` /
  `resolve_contested_transitions` do `sorted(districts)` full passes every turn.
- **`incidents.py` / `_surface_new_incidents`** — in every region's skip list, but runs per-turn over
  all districts and per-decision over targets. Uncosted.

**Heavy functions worth a future deep look:** `generate_audit_result` (the second foldable pass at
355-376 overlapping `_scenario_score`); `scorecard` as called from `_ledger_rows`; the
`buyouts.py` round resolvers; `_city_forecast_bucket`'s downstream rules chain
(`_district_adjusted_effects`/`_land_use_adjusted_effects`/`_service_coverage_effect`/`_merge_delta`)
— invoked on *both* the action and render paths, so one fix there pays off twice.

## 4. Dropped as already-done (excluded from the ranked list)

The synthesis stage removed these after cross-referencing `docs/decisions.md` + commit `7e0a22e`:

- **reload-state memoization / per-item proposal-visibility cursor scans** — done (ADR-5; single
  `proposal_visible_map()` pass). Only the residual second comprehension survives, kept as #30.
- **refresh-only layer rebuild / SHAPE@ geometry memo / `active_item` single read** — done (ADR-4/5).
- **WHERE-clause single-row store/geometry cursors** — done (ADR-5; `store.py:777,820`). The
  *multi-row* writes (#14, #15) are distinct and **not** covered — they're kept in the list.
- **`_eligible_bidders` decorate-sort / drop pre-shuffle** — self-invalidated: `sorted()` computes the
  key once per element (no per-comparison recompute), and the `rng.shuffle` is the load-bearing ADR-11
  tie-break. No real win.
- **`selected_cell_ids` FIDSet branch typing** — observe-only, can't claim a win without knowing the
  live ArcPy `Describe` path. The actionable part (the `ListFields` scan) is kept as #27.
- **Skip dissatisfaction before/after double-sum** — self-invalidating; cascades can shift
  dissatisfaction between snapshots, so the guard would rarely fire safely. The genuine win here is #9.
- **Fuse post-failure per-target passes in `resolve_decision`** — subsumed by #9 for the safe portion;
  the remaining fusion is ordering-sensitive and untraced.
